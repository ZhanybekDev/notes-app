# Тестовое задание — Notes App

Фича: **Telegram-напоминания по дате заметки**. Ветка `feat/telegram-note-reminders`.

---

## 1. Ссылка на форк

_Заполнить перед отправкой:_ `https://github.com/<username>/notes-app`, ветка
`feat/telegram-note-reminders`. Форк на момент написания не создан — нужен доступ к GitHub-аккаунту.

## 2. Чем делал

Claude Code, модель Claude Opus 5. Из инструментов внутри сессии — Docker Compose для прогона
стека, `pytest`/`vitest` для тестов, `ruff`/`eslint` для линта, веб-поиск для сверки актуального
поведения Bot API (лимиты, `retry_after`, `409 Conflict` при двух поллерах).

## 3. Почему именно это

Задача — не «написать код по спеке», а войти в чужой репозиторий и не сломать его, поэтому
ценность была в инструменте, который держит в контексте весь проект целиком и может сам гонять
тесты и линт в цикле, а не подсказывает по одному файлу. Плюс перед реализацией прогнал план
через adversarial-ревью: восемь проходов, и это окупилось — см. пункт 4, половина найденного
там была бы поймана только на проде.

## 4. Что заметил в scaffold

**Что понравилось.** `docs/architecture.md` — редкость для тестового: зафиксированы не только
компоненты, но и правила зависимостей («роутеры не импортируют друг друга», «`api.js` —
единственный, кто вызывает `fetch`», «новый env-var идёт через `app/config.py`»). Я по ним и
сверялся, потому что `CLAUDE.md`/аналога в репозитории нет. Snapshot-тест на дрейф
`openapi.json` и порог покрытия в `pytest.ini` — тоже хорошие, дешёвые гейты.

**Что спорно.**

- **`make lint` красный на чистом клоне.** `ruff format --check` спотыкается на
  `tests/test_auth.py:90`. То есть DoD пункт 3 не выполняется ещё до чьих-либо изменений.
  Починил первым делом.
- **`rate_limit.py` — счётчики в модульном `dict`.** Не переживает рестарт и не работает при
  нескольких воркерах uvicorn: лимит на подбор пароля обходится рестартом контейнера. Ровно тот
  же соблазн был и в моей задаче («запомним отправленные напоминания в памяти»), поэтому состояние
  доставки у меня в БД, а не в процессе. Замену `rate_limit.py` на persistent не делал — это за
  границами задания.
- **`JWT_SECRET` захардкожен в `docker-compose.yml`** при том, что `config.py` специально
  валидирует секрет на «слабость». Защита есть, а дефолт в compose её обходит.
- **Фильтр по тегам в `notes.py` тянет все заметки пользователя в память** (`query.all()` →
  сортировка → срез в Python) и там же считает `total`. На паре сотен заметок незаметно, дальше —
  нет. Не трогал: не моя задача, и это меняет поведение пагинации.
- **Парность EN/RU не проверяется тестом.** `i18n.test.jsx` тестирует механику провайдера и одну
  русскую строку; забытый перевод не поймает никто. DoD требует парности — держал вручную.
- **Тесты идут на SQLite, прод на Postgres.** В `architecture.md` это честно оговорено, но
  расхождение реальное: `FOR UPDATE SKIP LOCKED` на SQLite молча игнорируется, так что блокировку
  пришлось проверять по скомпилированному SQL, а не поведением.
- **`.env.example` лежит в `backend/`, а `docker-compose.yml` его не использовал вообще** — все
  переменные захардкожены inline. Рассинхрон между тем, где переменные задокументированы, и тем,
  откуда читаются.

## 5. Что бы сделал следующим заходом

- **Persistent rate limiting** вместо in-memory (Redis или таблица) — сейчас защита обходится
  рестартом.
- **Тест на парность ключей EN/RU** — обход двух словарей и `assert` на совпадение множеств.
  Пять строк, закрывает целый класс регрессий и пункт 6 DoD.
- **Пагинация по тегам на стороне БД** — JSONB-оператор для Postgres за фичефлагом диалекта,
  чтобы не тащить всё в память.
- **Дайджест вместо потока сообщений** — если на один день заметок десять, придёт десять
  сообщений. Группировка в одно с перечнем.
- **Deep-link на заметку в тексте напоминания** — сейчас его нет, потому что роута `/notes/:id`
  в приложении не существует; нужен роутинг по заметке.
- **CI** — в `main` его нет. Прогон `make lint` + `make test` на PR.
- **Webhook вместо long polling** для продакшена — polling выбран сознательно, чтобы `make up`
  работал без публичного URL.

## 6. Known caveats — честно

- **Видео не записано.** Требует человека: чтобы бот мог написать пользователю, тот должен сам
  нажать **Start** в Telegram — обойти это со стороны сервера нельзя. Пошаговый сценарий для
  записи — в `docs/demo.md`, шаги 2–3.
- **Привязка через `/start` не проверена на живом чате** по той же причине. Проверено всё
  остальное: воркер поллит реальный Bot API (`getUpdates` → 200 OK), `getMe` подтверждает токен,
  а путь доставки прогнан против настоящего API с заведомо несуществующим `chat_id` — Telegram
  ответил `400 Bad Request: chat not found`, напоминание осталось `pending` с `attempts=1`,
  воркер продолжил работу. То есть отработали материализация, claim, отправка, обработка ошибки и
  ретрай; не подтверждена только последняя миля — доставка в настоящий чат.
- **Форк не создан**, ссылка в пункте 1 не заполнена.
- **Изменения не закоммичены** — лежат в worktree на ветке `feat/telegram-note-reminders`.
- **Конкурентный claim проверяется по SQL, а не поведением.** `FOR UPDATE SKIP LOCKED` на SQLite
  (диалект тестов) — no-op, поэтому тест утверждает наличие блокировки в скомпилированном под
  Postgres запросе. Практическая защита от дублей покрыта иначе: два прогона `tick()` подряд дают
  ровно одну отправку.
- **Коллизия `telegram_chat_id` отдаётся сообщением бота, а не HTTP 409.** Привязку завершает
  воркер, а не API, так что HTTP-пути у этой ошибки просто нет; пользователь получает внятный
  ответ в чате.
- **`docker compose logs worker` не показывает токен**, но это пришлось чинить отдельно: `httpx`
  логирует полный URL запроса на уровне INFO, а токен живёт именно в URL. Логгер `httpx` приглушён
  до WARNING. Если кто-то поднимет уровень логирования обратно — токен снова окажется в логах.
- **Токен бота из демо светился в открытом виде** в переписке при разработке. Для тестового бота
  некритично, но перед публикацией форка его стоит отозвать через `/revoke` у @BotFather.
- **Реплика воркера ровно одна.** Не ограничение реализации, а Bot API: второй одновременный
  `getUpdates` на тот же токен получает `409 Conflict`. Масштабируется только отправка.
- **Один Telegram-аккаунт — один аккаунт в приложении.** Ограничение осознанное (`UNIQUE` на
  `telegram_chat_id`), попытка привязать занятый чат отклоняется.
- **Заметок без даты и архивных напоминания не касаются** — как и заметок старше 24 часов: окно
  backfill не даёт при первом запуске разослать всю историю.

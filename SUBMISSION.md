github.com/selimdev00/notes-app, ветка feat/telegram-reminders

2. чем делал
claude-code на opus. весь цикл на нём - код, тесты, локальный запуск в docker и живая проверка end-to-end через браузер с реальным ботом.

3. почему так
репо чужое и с жёсткими гейтами - порог покрытия, снапшот openapi, рабочий downgrade миграции, en/ru. агент, который правит сразу backend+worker+фронт и сам гоняет make test/make lint в цикле, тут заходит лучше чем руками. меньше шансов где-то рассинхронить слои.

4. что заметил в scaffold
- note_date это голый date без времени, так что напоминание по дню, не по часу. "дата наступила" трактую как начало этого дня в таймзоне юзера.
- бэк это один uvicorn --reload, фоновых джоб нет вообще, идемпотентности тоже. ровно та дыра, которую фича и закрывает. планировщик вынес в отдельный worker-контейнер, чтобы не драться с --reload и держать один консьюмер getUpdates.
- ruff не запинен (ruff>=0.5). свежий ruff переносит уже существующую длинную строку в tests/test_auth.py, и make lint краснеет на нетронутом чекауте. эту строку поправил и запинил ruff на конкретную версию.
- тесты не герметичны к окружению: если в env лежит TELEGRAM_BOT_TOKEN, он протекал в pytest внутри контейнера и менял поведение. добавил autouse-фикстуру, которая сбрасывает telegram-настройки, теперь детерминировано независимо от env.
- снапшот-тест на openapi - огонь, сразу поймал новые ручки ))
- сам ui/ux выглядит очень ai-шно - типовые карточки, эмодзи прямо в кнопках (пин, архив, дата), дефолтные отступы. помимо задания я бы переделал интерфейс по-человечески: убрал эмодзи-иконки на нормальный icon-set, навёл сетку, состояния и пустые экраны. свою часть (telegram, таймзона, экспорт, шеринг) вписывал в существующий стиль, чтобы не выбивалась.

что поймал на самопроверке и починил ДО отправки (прогнал свой же дифф через два адверсариал-ревью):
- было: строку в reminders_sent писал ПОСЛЕ отправки. при конкурентных воркерах сообщение реально могло уйти дважды (unique защищал только запись, не доставку). стало: claim-first - insert+commit клейма ДО отправки, unique(note_id, note_date) гейтит саму доставку.
- worker двигал offset getUpdates до обработки апдейта - на исключении апдейт терялся. теперь offset двигается после обработки, handle_update не бросает.
- экспорт в ui дёргался без обработки ошибок - молча падал на 401. добавил try/catch + показ ошибки.

сверх задания, для порядка в репе:
- CI на GitHub Actions, гоняет ровно DoD-гейты (ruff + pytest + openapi-drift + eslint + vitest) на каждый push/PR. в scaffold CI не было. прогнал её локально через act - и она сразу поймала два бага, которые упали бы и на реальном GitHub: незаэкранированный sqlite:///:memory: в yaml и package-lock.json без linux-бинаря rollup (npm ci падал бы на любом linux-раннере). оба починил, lockfile перегенерил кросс-платформенным.
- тест на worker (handle_update) - закрыл единственный непокрытый модуль. + worker валидирует токен через getMe на старте вместо вечного ретрая.
- описал фичу в docs/architecture.md (worker-сервис, claim-first, ручки).
- второй опциональный бонус - public read-only share (миграция + публичная ручка + ui + en/ru + тесты).

5. следующим заходом
- webhook вместо поллинга getUpdates. привязка мгновенная и без вечного консьюмера.
- напоминания по времени а не по дню, когда у note_date появится time.
- горизонтальное масштабирование воркера через SELECT ... FOR UPDATE SKIP LOCKED. сейчас хватает claim-first + unique.
- таймзона полным списком IANA с поиском, сейчас урезанный набор для демо.
- переделать ui/ux по-человечески - главный мой не-функциональный пункт.

6. known caveats
- дважды сообщение не уйдёт даже при нескольких воркерах (claim-first + unique гейтит доставку). зато доставка at-most-once: крэш ровно между успешной отправкой и удалением клейма на фейле в худшем случае потеряет одно напоминание, но не задвоит.
- первый раз включаешь напоминания, а в заметках лежат старые даты в прошлом - они все стрельнут на ближайшем тике (note_date <= сегодня). это by design "дата наступила", но знать стоит.
- меняешь дату заметки на другой день - снова станет eligible (ключ (note_id, note_date)).
- невалидный токен теперь ловится на старте воркера через getMe и он уходит в idle, а не крутит вечный ретрай.
- линк-код 15 мин и одноразовый, но кто откроет ссылку и нажмёт start - тот и привяжет свой чат (deep-link не сверяет веб-аккаунт с telegram-юзером). тело напоминания содержит заголовок и кусок текста заметки.
- public share: ссылка с токеном даёт read-only доступ кому угодно по ссылке (как gist/pastebin), отзывается кнопкой. сам токен 128 бит.
- демку гонял на одноразовом боте, токен в репо не коммитил (gitignored .env). команды для воспроизведения - в DEMO.md.

# Notes — заметки с напоминаниями в Telegram

Личные заметки в Markdown: теги, поиск, дата и календарь, напоминания в Telegram в день заметки,
публичные ссылки только на чтение и экспорт в markdown или zip. Тёмная тема, интерфейс на русском и
английском.

Английская версия документации — [`README.md`](README.md). Разбор решений и известные ограничения —
[`SUBMISSION.md`](SUBMISSION.md), устройство изнутри — [`docs/architecture.md`](docs/architecture.md).

## Быстрый старт

Это для локального запуска; чтобы просто посмотреть, ставить ничего не нужно — см. раздел выше.

**Нужен только Docker с Compose.** Ни Python, ни Node на машине ставить не надо — всё собирается в
контейнерах.

```bash
git clone https://github.com/ZhanybekDev/notes-app.git
cd notes-app

make up      # поднимает postgres + backend + worker + frontend
make seed    # демо-пользователь и пять заметок
```

Через полминуты:

| Что | Адрес |
|---|---|
| Приложение | http://localhost:5173 |
| API | http://localhost:8000 |
| Swagger | http://localhost:8000/docs |
| Проверка живости | http://localhost:8000/healthz |

Вход: **`demo` / `demo1234`**.

**Что делает `make up`:** собирает образы, поднимает Postgres, ждёт его готовности, прогоняет
`alembic upgrade head` (миграции применяются сами при старте бэкенда), запускает uvicorn с
автоперезагрузкой, воркер Telegram и Vite dev-сервер. Повторный запуск безопасен: миграции
идемпотентны, `make seed` пересоздаёт заметки демо-пользователя, а не плодит их.

**Остановить:** `make down`. **Стереть базу вместе с данными:** `make clean`.

## Переменные окружения

Живут в `backend/.env` (шаблон — `backend/.env.example`) и в `environment` у сервисов
`docker-compose.yml`. Значения из compose перекрывают файл.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg2://postgres:postgres@db:5432/notes` | подключение к БД |
| `JWT_SECRET` | — обязательна | подпись токенов; на старте проверяется на длину и «слабость», так что `secret` или `changeme` не пройдут |
| `JWT_EXPIRE_MINUTES` | `1440` | срок жизни токена, сутки |
| `CORS_ORIGINS` | `http://localhost:5173` | список источников через запятую |
| `TELEGRAM_BOT_TOKEN` | пусто | токен бота от @BotFather |
| `TELEGRAM_BOT_USERNAME` | пусто | имя бота без `@`, нужно для deep link привязки |

**Без токена бота приложение работает полностью**, кроме напоминаний: воркер видит, что бот не
настроен, пишет об этом в лог и стоит в простое, а экран настроек честно говорит, что интеграция
недоступна.

## Telegram-бот

### Как подключить

1. Создать бота: у **@BotFather** → `/newbot` → имя → username → он выдаст токен.
2. Положить токен и username в `backend/.env`:

   ```
   TELEGRAM_BOT_TOKEN=123456:AA...
   TELEGRAM_BOT_USERNAME=my_notes_bot
   ```

3. Перезапустить: `make down && make up`.
4. В приложении: **Настройки → Telegram → «Подключить»**. Откроется чат с ботом и заранее
   подставленной командой `/start <код>` — нажать «Start».
5. Экран сам обновится на «подключено»: страница спрашивает сервер, дошла ли привязка, а не просит
   перезагрузить вкладку.

Код привязки живёт **15 минут** и одноразовый. Один Telegram-аккаунт — один аккаунт в приложении;
попытка привязать уже занятый чат отклоняется внятным сообщением в чате.

### Команды

Публикуются через `setMyCommands`, поэтому видны в меню бота, и тот же список отдаёт `/help` — они
не могут разойтись.

| Команда | Что делает |
|---|---|
| `/today` | что запланировано на сегодня |
| `/upcoming` | датированные заметки на 7 дней вперёд |
| `/status` | как подключён этот чат: аккаунт, пояс, время напоминаний, включены ли они |
| `/pause` | приглушить напоминания, не отвязывая чат |
| `/resume` | включить обратно |
| `/help` | показать список |

`/start` в меню намеренно нет — она приходит по deep link при привязке, а не выбирается руками.

Списки обрезаются десятью пунктами, заголовки — 80 символами: сообщение должно оставаться читаемым в
телефоне. `/pause` и `/resume` пишут прямо в настройки аккаунта, поэтому переключатель в интерфейсе
показывает то же самое — это одно состояние, а не два.

**Язык бота** берётся из Telegram (`language_code` при привязке) и запоминается, чтобы напоминание
через неделю читалось так же, как приветствие. Следствие: русский интерфейс и английский Telegram
дадут английские сообщения бота.

## Как работают напоминания

**Заметке задаётся дата, время берётся из настроек.** Дата — это день, а не момент; час и минута
общие для аккаунта (`Настройки → Время напоминания`, по умолчанию 09:00) и считаются в вашем часовом
поясе.

> Заметка на 1 августа, пояс `Asia/Bishkek`, время 09:00 → отправка 1 августа в 09:00 по местному,
> то есть в 03:00 UTC. В базе всё хранится в UTC.

Под полем даты в редакторе стоит подсказка, которая сразу проговаривает результат: «Напоминание
1 августа в 09:00», «Этот момент уже прошёл» или «Напоминания выключены» со ссылкой в настройки.

**Напоминание придёт, если выполнены все четыре условия:** у заметки есть дата, она не в архиве, в
настройках включены уведомления, привязан Telegram. Условия проверяются дважды — при планировании и
прямо перед отправкой, потому что заметку могли изменить в промежутке, а сообщение не отзывается.

**Что делает воркер каждые 30 секунд:**

1. гасит запланированные отправки, у которых условия перестали выполняться;
2. создаёт записи для заметок в окне **до 48 часов вперёд**;
3. пересчитывает время, если сменились пояс или время напоминания;
4. отправляет то, что подошло по времени.

**Окно назад — 24 часа:** напоминание старше суток не уйдёт никогда, иначе первый запуск после
простоя разослал бы всю историю разом.

**Точность — около минуты.** Тик раз в 30 секунд плюс long-poll до 25 секунд: в живом замере
сообщение ушло через 48 секунд после расчётного момента. Для напоминания по дате заметки это
несущественно, и точности «до секунды» фича не обещает.

**При сбое:** пять попыток, ошибка и счётчик пишутся в саму запись; после исчерпания она помечается
неудачной, а не крутится вечно. На `429` воркер ждёт ровно столько, сколько просит Telegram.

## Публичные ссылки и экспорт

**Ссылка только на чтение.** В редакторе открытой заметки — «Поделиться»: появляется адрес вида
`/s/<токен>`, который открывается без входа в приложение. Повторное нажатие не выпускает новый токен,
чтобы не сломать уже отправленную ссылку. «Отозвать» гасит её навсегда — новый шер даст другой токен.
Архивация заметки временно отключает ссылку, разархивация возвращает; удаление убирает совсем. По
ссылке видны только заголовок, текст, теги и дата — ни имени владельца, ни служебных полей.

**Экспорт.** Кнопка «Экспорт» в редакторе скачивает одну заметку файлом `.md` с front matter
(заголовок, дата, теги). `Настройки → Экспортировать все заметки` отдаёт zip из markdown-файлов и
уважает те же фильтры, что список: поиск, тег, вкладка «Архив».

## Разработка

```bash
make help          # список целей
make logs          # хвост логов всех сервисов
make test          # backend (pytest + покрытие) и frontend (vitest)
make lint          # ruff check + format, eslint
make migrate       # alembic upgrade head вручную
make openapi-dump  # перегенерировать backend/openapi.json после правки эндпойнтов
make clean         # остановить и удалить том с базой
```

**Тесты:** 237 на бэкенде при пороге покрытия 80% (фактически ~96%) и 229 на фронте. Бэкенд тестируется
на SQLite в памяти, прод — Postgres; расхождение оговорено в `docs/architecture.md`.

**Новая миграция:**

```bash
docker compose exec backend alembic revision -m "что делает"
# отредактировать upgrade() и обязательно downgrade()
docker compose exec backend alembic upgrade head
```

**Правка эндпойнта** требует `make openapi-dump` — снапшот `backend/openapi.json` защищён тестом и
уронит сборку, если о нём забыть. Это специально.

**Новая строка интерфейса** добавляется сразу в оба каталога `frontend/src/messages.js`: тест сверяет
множества ключей EN и RU и ловит пустые значения.

## Деплой

Рабочий инстанс — **https://notes.ssi-dev.com**, поднимается из `docker-compose.prod.yml`.

```bash
cp .deploy.env.example .deploy.env   # адрес сервера, файл в .gitignore
./deploy.sh                          # залить, пересобрать, мигрировать, дождаться /healthz
```

Чем прод-стек отличается от dev-стека:

| | dev (`docker-compose.yml`) | прод (`docker-compose.prod.yml`) |
|---|---|---|
| Исходники | смонтированы в контейнер | вкомпилированы в образ |
| Бэкенд | `uvicorn --reload` | без reload, `--proxy-headers` |
| Фронтенд | Vite dev server | собранный бандл в nginx |
| `/api` | прокси Vite | прокси nginx (тот же origin) |
| Секреты | dev-значения в compose-файле | только `.env` на сервере, `chmod 600` |
| Postgres | порт наружу (5433) | наружу не публикуется |

Три решения, которые стоит назвать явно:

- **`try_files … /index.html` в nginx.** Маршруты `/notes`, `/calendar`, `/s/<token>` существуют
  только внутри бандла. Без фолбэка публичная ссылка — единственный URL, который открывают
  посторонние, — отдавала бы 404 от nginx.
- **`deploy.sh` ждёт `/healthz`, а не завершения `up -d`.** Второе наступает раньше, чем
  применятся миграции: «деплой прошёл» в терминале и 502 в браузере.
- **Адрес сервера — в `.deploy.env`, а не в скрипте.** Скрипт с зашитым адресом публикует
  устройство приватной сети всем, кто открыл репозиторий.

Секреты не попадают ни в git (`.gitignore`), ни в образ (`.dockerignore`), ни на сервер поверх
существующих (`rsync --exclude .env`). В репозитории лежит только `.env.prod.example` с пустыми
значениями. База переживает деплой — она в docker-томе, который `deploy.sh` не трогает.

### Один токен — один воркер

Развёрнутый воркер держит long polling постоянно, а Bot API отвечает `409 Conflict` на второй
одновременный `getUpdates` по тому же токену. Практическое следствие: **пока работает прод-инстанс,
локальный `make up` с тем же токеном ломает обоих** — апдейты уходят то одному, то другому, и живой
бот выглядит «отвечает через раз». Для локальной разработки нужен отдельный бот от @BotFather;
токен в `backend/.env` не должен совпадать с серверным.

Это не ограничение реализации, а свойство Bot API: webhook на прод и polling локально развели бы
процессы, но webhook требует публичного адреса у каждой машины, где ведётся разработка.

## Зависимости

**Бэкенд:** FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, PyJWT, passlib+bcrypt, httpx, psycopg2.
Тесты — pytest, ruff. Ни планировщика, ни очереди: воркер — обычный процесс с циклом, состояние
доставки в таблице, а не в памяти.

**Фронтенд:** React 18, react-router, react-markdown, **zustand** — единственная добавленная сверх
scaffold зависимость (MIT, ноль транзитивных). Тесты — vitest, Testing Library. Сборка — Vite.
Стили написаны руками: ни CSS-фреймворка, ни библиотеки компонентов, ни библиотеки анимаций.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `Internal Server Error` после `git pull` | контейнер бэкенда стартовал до новых миграций: `make migrate` |
| Воркер пишет «bot is not configured» | нет `TELEGRAM_BOT_TOKEN`/`TELEGRAM_BOT_USERNAME` — приложение работает, напоминаний нет |
| В логе `409 Conflict` у воркера | запущен второй экземпляр с тем же токеном: Bot API разрешает ровно один `getUpdates`. Частный случай — локальный `make up` при работающем прод-инстансе, см. ниже |
| Живой бот перестал отвечать после локального `make up` | тот же токен, два поллера: локальный воркер отбирает апдейты у сервера. Для разработки нужен **отдельный бот** от @BotFather — токен в `backend/.env` не должен совпадать с тем, что на сервере |
| Фронт не собирается после `npm install` в контейнере | пересобрать образ: `docker compose build frontend && docker compose up -d --force-recreate --renew-anon-volumes frontend` |
| Напоминание не пришло | проверьте четыре условия: дата у заметки, не в архиве, уведомления включены, чат привязан. И окно: старше суток не отправляется |
| `make lint` красный на чистом клоне | так и было в исходном scaffold (`ruff format` на `tests/test_auth.py`), в этой ветке починено |

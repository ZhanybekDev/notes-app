## Critical Findings

### C13 — регрессионная сеть для самого рискованного шага не существует

- **Dimension:** D11 / D6
- **Problem:** план дважды опирался на одну и ту же страховку: шаг 3 фазы 1 — «механический перенос
  204 блоков без изменения значений **с прогоном 142 тестов**», и тот же аргумент в разделе рисков.
  Проверка `vite.config.js:19`:

  ```js
  test: { environment: 'jsdom', globals: true, setupFiles: './src/test/setup.js', css: false }
  ```

  `css: false` означает, что vitest стили **не обрабатывает вообще**. Тесты останутся зелёными, даже
  если переезд потеряет половину файла: они проверяют разметку и логику, а не то, что к ней
  применилось. Самый механический и самый объёмный шаг плана шёл без единой автоматической проверки,
  и при этом план утверждал обратное — это хуже, чем отсутствие проверки, потому что снимает
  настороженность.
- **Applied:** тест-стратегия фазы 1 переписана. Названо прямо, что тесты CSS не видят; настоящая
  автоматическая проверка — `npm run build` (единственный шаг, обрабатывающий CSS: поймает битый
  `@import`, синтаксис, неразрешённый путь) плюс сверка размера собранного CSS с текущими **22.67 kB**
  при допуске ±15% — грубый, но реальный признак, что блоки не потерялись и не продублировались.
  Визуальная эквивалентность — руками, и это сказано без эвфемизмов. Раздел рисков переписан
  соответственно; добавлен критерий приёмки на сборку и размер.
